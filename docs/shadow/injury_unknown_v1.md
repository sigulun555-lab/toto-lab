# 試験（shadow）：欠場・負傷情報の「不明」を0人扱いしない（v1）

作成：Claude（2026-11-12）。担当の決定は #90 の作業分担（順位1）に基づく。
**本番の予想は変更しない。** 採用の判断は東海林さんが行う。

## 背景
- 現在の本番では、情報が確認できなかった選手を「欠場0人」として扱っている。
- その結果、実際には負傷者がいても補正が入らない試合が出る可能性がある。

## 状態の定義（選手ごと、試合ごと）
| status | 意味 |
|---|---|
| `confirmed_out` | 欠場・出場停止が一次ソースで確認できた |
| `confirmed_available` | 出場が一次ソースで確認できた、または欠場なしと確認できた |
| `unknown` | 確認できなかった（本番では0人扱い。試験では「不明」として扱う） |

## 試験の計算ルール（shadow）
1. 本番と同じ計算を行う（攻撃側6%・守備側6%、上限3人）。
2. 試験では、`unknown` の選手は補正に含めない（0人扱いと同じだが、**記録上は「不明」と残す**）。
3. 試験の出力は、試合ごとに次の3つを記録する：`confirmed_out` の人数、`unknown` の人数、補正の有無。
4. `unknown` が1人以上ある試合は、「確認が不十分」フラグを付ける。

> 注：v1 の試験は、本番と同じ数値になる（unknown を0とみなす）。目的は、**どれだけの試合で情報が不明なまま予想しているかを数えること**と、確認できた試合だけの比較を作ること。補正の大きさを変える試験は v2 で扱う。

## 記録の形式
`data/injury_status/round_<回番号>.jsonl`（1行1選手）：
```json
{"round":1672,"matchNumber":1,"team":"チーム名","player":"選手名","status":"confirmed_out","sourceUrl":"https://...","sourceAt":"2026-11-13T10:00:00+09:00","recordedAt":"2026-11-13T10:05:00+09:00"}
```
- 出典（sourceUrl）と時刻（sourceAt）は必須。出典がない行は書かない。
- 既存の行は書き換えない（追記のみ）。
- 締切後に確認した情報は、**締切後**の時刻で記録し、締切前の予想とは区別する。

## 評価
- 対象：`unknown` が0の試合（確認済みの試合）と、`unknown` を含む試合を分けて集計する。
- 指標：LogLoss・Brier（小さいほど良い）。的中は補助。
- 判定：候補 − 基準（paired）の日付ブロック bootstrap 95% 区間の上限が0未満で、両指標とも改善していること。
- 件数の目安：最低 10 ラウンド・30 試合。

- 推測で埋めない。不明は `unknown` のまま記録する。
